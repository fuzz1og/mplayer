# 移动端推荐页 / 我的歌单页改版 — 规格

> 日期：2026-11-16 · 分支：`claude/ui-ux-page-review-de756f` · 来源：发现页改版后的第二轮视觉收敛
> 状态：已实施（2026-11-16，未提交）。方向板与原型均为会话资产（`design/prototypes/`），不入库。
> 工单：#748（推荐页）、#749（歌单页）。
> 决策：推荐页采用「一张电台」，歌单页采用「收藏做主卡」；歌单主图一律取第一首歌封面，不做歌曲拼图。

## Problem Statement

推荐页的「今日推荐」标题、5 首歌列表与下方「猜你喜欢」各自成段：每日 5 首既占一个 section，又和下方推荐歌单形成两个入口，首屏没有唯一的「现在听什么」。歌单页把收藏、播放历史与自建歌单都做成同样的图标行，收藏没有视觉重量，自建歌单也没有封面，层级扁平。

用户已选定：推荐页用「一张电台」把每日 5 首收进一张卡；歌单页用「收藏做主卡」，收藏升为一张主卡，播放历史与本地歌曲降为紧凑入口，自建歌单保持标准行。歌单主图不要 2×2 歌曲拼图，直接用第一首歌的封面。

## Solution

- **推荐页**：删除独立的「今日推荐」标题与列表段，改成一张「每日推荐」电台卡：卡头是当前批次前 3 张封面叠放 + 标题 + 「5 首 · 24 分钟」+ 播放全部 / 换一批，卡内是当前批次 5 行歌曲。下方「猜你喜欢」保持两列纵向网格（横向滑动不符合列表直觉）。播放全部仍只入队当前可见批次。
- **我的歌单**：收藏升为一张横向主卡（首曲封面 + 标题 + 数量 + 播放键）；播放历史、本地歌曲合并成一张紧凑分组卡；自建歌单按标准行展示，行首用第一首歌封面。新建入口放在「自建歌单」组头右侧，不再单独占一行。保留长按删除，不新增排序等未实现动作。
- **导航**：本地歌曲从底部 tab 移入 Stack（入口在歌单页的本地歌曲行），底部只留推荐 / 发现 / 歌单三个 tab；保存位置移到设置页「下载」区段。
- **歌单封面规则**：应用自己生成的歌单主图只取 `songs[0].cover`，单图裁切；无歌或无封面时用中性占位图标，不拼 2×2、不拼 3 张。收藏主卡取 `favorites[0].cover`。发现页/搜索里的平台歌单继续用源返回的单张 `coverImgUrl`，不在此规则内。

## User Stories

1. 作为推荐页用户，我希望每日 5 首只出现一次，并和「播放全部 / 换一批」在同一张卡里，以便不用在两段内容之间判断从哪里开始。
2. 作为推荐页用户，我希望卡片告诉我这批歌有几首、大约多久，以便决定现在是否开始听。
3. 作为推荐页用户，我希望「猜你喜欢」用两列纵向网格浏览，符合列表直觉。
4. 作为歌单页用户，我希望收藏是一张明显的主卡并可直接播放，以便最常用的入口一眼可见。
5. 作为歌单页用户，我希望播放历史与本地歌曲是紧凑入口，不和自建歌单抢层级。
6. 作为歌单页用户，我希望每个自建歌单显示第一首歌的封面，以便靠封面快速认出歌单。
7. 作为歌单页用户，我希望空歌单有明确占位，而不是空白或拼图。
8. 作为读屏用户，我希望收藏主卡、紧凑入口和歌单行都有完整名称与数量，而不只是「播放」。
9. 作为维护者，我希望封面规则只有一处来源，避免推荐页、歌单页、歌单详情各写一套。

## Implementation Decisions

### 1. 推荐页（`packages/mobile/app/(tabs)/recommend.tsx`）

- 内容顺序：每日推荐卡 → 猜你喜欢两列网格。页面不再有独立「今日推荐」标题。
- 卡头：当前批次前 3 张封面叠放（无封面时用 `Music` 图标占位）；标题「每日推荐」；meta `${n} 首 · ${m} 分钟`，`m = round(sum(duration) / 60)`，`duration` 缺失或为 0 时不参与，全部缺失时只显示 `${n} 首`。
- 卡头动作：主按钮「播放全部」（accent 实底，点击入队当前批次并从第 1 首播放）；次按钮「换一批」（沿用 `pickRandomBatch` 与 `canShuffle`，池不足一批时禁用）。
- 卡身：现有 `SongRow` 逐行渲染当前批次；队列仍是当前批次，不把 100 首池入队。
- 猜你喜欢：两列纵向网格（`gridCardWidth` / `GRID_CARD`），封面宽高同卡宽、12 圆角，名称 2 行、播放量 1 行；点击进 `/discover-playlist/:id`。
- 骨架屏 `RecommendSkeleton` 同步改成「卡头 + 5 行 + 两列网格」同形；行数与列数继续从 `recommendMetrics` 取。
- 不动接口、随机池大小、错误态与下拉刷新。

### 2. 我的歌单（`packages/mobile/app/(tabs)/playlists.tsx`）

- 页头：不再显示「我的歌单」；新建入口放在「自建歌单」组头右侧（`+ 新建`），组头始终显示。
- 收藏主卡：整卡可点进 `/favorites`；左侧 100×100 首曲封面（无封面用 `Heart` 占位），右侧标题「我喜欢的音乐」、`${favorites.length} 首 · 最近更新`、44pt accent 播放键。播放键入队全部收藏并从第 1 首播放，事件不冒泡到整卡。
- 紧凑分组：播放历史（`history.length` 首）→ `/history`；本地歌曲（`downloadStore` 中 `status === 'done'` 的数量）→ `/download`。两行共用一张分组卡与分隔线。
- 自建歌单：组标题「自建歌单」+ 数量；每行 48×48 首曲封面、名称、`${songs.length} 首 · ${createdAt}`；空歌单用 `ListMusic` 占位。长按删除沿用现有确认框。
- 封面取 `songs[0]`，用 `useRefreshedCover` 处理失效刷新；行内不渲染多张图。
- 空状态：自建歌单为空时组头与新建入口仍显示；收藏为 0 时主卡仍显示，播放键禁用并降低不透明度。

### 3. 导航与本地歌曲

- 底部 tab 从四个减为三个：推荐 / 发现 / 歌单；`TABS` 与 `Tabs.Screen` 同步移除 `download`。
- `(tabs)/download.tsx` 移到 `app/download.tsx`，在根 Stack 注册；页名由原生 header「本地歌曲」承担，底部只留 `BottomSafePlayerBar`，不再有 tab chrome。
- 歌单页本地歌曲行改用 `router.push('/download')`；路径仍是 `/download`，深链不变。
- 保存位置从本地歌曲页移到设置页新的「下载」区段（`DownloadSettingsSection`）：显示当前目录，点击打开系统目录选择器；路径与授权提示跟随迁移。

### 4. 封面规则

- 新增一个纯函数 `playlistCoverSong(songs)`（返回 `songs[0] ?? null`）供歌单页与后续入口复用；歌单详情 `PlaylistHero` 已按首曲封面实现，不重复改。
- 占位优先级：首曲封面 → 刷新后的封面 → 中性图标。禁止 2×2 / 多图拼接。

### 5. 页面标题与清空入口（2026-11-17 追加）

- 页面身份已由底部 tab / 原生 header 承担，内容区不再重复可见页名。审计结果只有两处：歌单页的「我的歌单」标题、播放历史页列表里的「播放历史」section header，均已移除；其他 tab 与带原生 header 的详情页无重复。
- 歌单页移除标题后，新建入口放在「自建歌单」组头，不额外占一行。
- 播放历史「清空」从列表内移到原生 header 右侧，用垃圾桶图标；点击先弹确认（取消 / 清空），空历史时不显示。

### 6. 状态页与行操作（2026-11-17 追加）

- `EmptyState` 扩展为 `page` / `embedded` 两档：标题统一 `sectionHeader`，动作统一 accent 胶囊按钮，支持 `actionIcon` 与 `iconColor`；空态用中性图标，错态用 `dangerText`。
- `DiscoverStateView` 只做 `EmptyState` 内嵌变体的发现页适配；新增 `InlineError` 统一列表底部/区块内重试，替换发现页、搜索页、歌手页、电台页各自手写的错误条。
- 搜索歌曲/歌手/歌单/电台失败均给重试；歌手页歌曲、专辑、电台失败均给重试。
- 空歌单给「去发现音乐」主操作；不存在的歌单给「返回」。
- 自建歌单行补行尾更多菜单（重命名 / 删除），长按删除保留；删除仍二次确认。
- TopBar 的搜索词只在搜索页显示；离开搜索页恢复「搜索歌曲...」占位，不再把上次查询带到推荐 / 发现 / 歌单页。

### 7. 视觉与可访问性

- 只用现有 token：`bgSurface`、`bgHover`、`borderSubtle`、`accent`、`accentSubtle`、`radius.md/lg`、`spacing`、`textVariants`；不新增颜色。
- 卡与分组不做实时模糊、不加新依赖；封面用 `LazyCover`，缩略图尺寸走 `COVER_SIZE`。
- 收藏主卡读屏名包含「我喜欢的音乐，N 首」；播放键单独命名「播放我喜欢的音乐」；紧凑行读屏名包含数量；歌单行读屏名包含名称与歌曲数。

## Testing Decisions

- 单元：`playlistCoverSong` 返回首曲、空数组返回 `null`；推荐页时长格式化（有/无 duration）。
- 静态守卫：推荐页与骨架屏仍从 `recommendMetrics` 取批次行数与网格列数；页面不出现 4 图拼图标记。
- 组件/页面：收藏为 0 时主卡播放键禁用；自建歌单空歌单显示占位；紧凑行跳转目标正确。
- 页面标题：歌单页内容区不再出现「我的歌单」标题；历史页不再出现列表内「播放历史」标题，清空只在 headerRight 且先确认。
- 状态页：EmptyState 的 page/embedded 两档共用标题与按钮；搜索歌曲/歌手/歌单/电台错误可重试；空歌单有主操作；歌单行更多菜单可重命名/删除。
- TopBar：搜索页外不显示上次查询词，输入框恢复占位。
- 导航：底部只有三个 tab；本地歌曲从歌单行进入后是 Stack 页（原生 header + 返回），保存位置出现在设置页「下载」区段。
- 静态门禁：`npm run verify -- mobile`（typecheck + mobile 测试 + design-lint）；真机抽查浅/深色、两列网格滚动、收藏主卡点击与播放键分隔、本地歌曲页与设置保存位置。
