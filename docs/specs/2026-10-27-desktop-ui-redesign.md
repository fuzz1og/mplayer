# 桌面端 UI 重构（1.9.0）—— SwiftUI 式原语与导航重组

> 日期：2026-10-27 · 分支：`feat/ui-redesign-1.9.0` · 来源：grilling 设计会话收敛，to-spec 留痕
> 设计语言：`docs/specs/ui-refactor-guide.md` · 决策：ADR `2026-10-27-desktop-ui-primitives-and-settings-shell.md`
> 原型：4 张 1:1 截图（资料库 / 设置·缓存 / 设置·外观 / 正在播放），随会话产出，不入库

## Problem Statement

桌面端的观感与结构都停留在「深色后台面板」：设置页同时铺开全局侧栏、设置二级导航与内容区三层，1225 宽下内容只剩约 740；每张卡片靠 1px 描边区分层级，卡内再套卡；11 个设置分区各配一个彩色图标；同一个「缓存占用」被 2×2 统计与「缓存构成」列表讲了两遍。组件层面混着 Ant Design 6 与大量内联样式（`src/renderer` 170 个文件里 1102 处 `style={{}}`、119 处色值字面量），控件节奏各写各的，看不出系统感。

用户要的是「像 SwiftUI 写出来的桌面应用」：分组列表的呼吸感、克制的层级、一个强调色、能一次看懂的导航；并且这次重构不能丢功能——每个现有入口在新界面上都必须点得到、测得着。

## Solution

用一套自建原语替换 Ant Design，重置导航与设置结构，把 16 个页面全部重画：

- **原语层**：11 个自建组件（按钮、标签、输入、开关、分段控件、进度、提示条、勾选、对话框、Toast、列表/网格）+ 3 个布局原语（分组卡、分区、设置行），提供 SwiftUI `insetGrouped` 式的分组列表。
- **导航层**：侧栏 9 项收敛为 6 项（设置移到标题栏右列文字按钮）；「本地音乐 / 下载管理 / 我的收藏 / 播放历史」合并进「资料库」页内的分段视图，四个入口各自仍可一次点到；播放队列移到播放栏按钮与全屏播放器的队列页。
- **设置层**：设置变为全屏视图（隐藏侧栏与播放栏，ESC/返回退出，播放不中断），11 个分区改为 3 组 7 页 + 底部固定「更新/关于」的下钻结构。
- **门禁层**：`design-lint` 扩到桌面端并改为严格模式，不限存量：禁止内联样式（仅允许 CSS 自定义属性形式）、禁止色值字面量、禁止 `antd` 引入、禁止字号/字重/圆角的字面量。

## User Stories

1. 作为桌面端用户，我希望侧栏只有 6 个入口（设置收进标题栏），以便一眼看完主导航。
2. 作为桌面端用户，我希望「资料库」一个入口下能切到全部/歌曲/专辑/歌手/下载/本地，以便不用在四个并列入口之间来回记位置。
3. 作为桌面端用户，我希望「下载管理」在资料库的「下载」分段里仍能开始、暂停、取消、打开目录，以便重构后照旧管理下载。
4. 作为桌面端用户，我希望「本地音乐」在资料库的「本地」分段里仍能扫描、播放、删除本地曲目，以便不丢功能。
5. 作为桌面端用户，我希望「我的收藏」与「播放历史」在侧栏保留快捷入口，同时也能从资料库进入，以便习惯路径不被破坏。
6. 作为桌面端用户，我希望播放队列能从播放栏一键打开，以便不离开当前页面就能看队列。
7. 作为桌面端用户，我希望全屏播放器里有队列页，以便在大屏状态下管理队列。
8. 作为桌面端用户，我希望点「设置」后进入全屏设置视图，以便内容不被侧栏和播放栏挤压。
9. 作为桌面端用户，我希望在设置里按 ESC 或点左上返回退出，以便不用找关闭按钮。
10. 作为桌面端用户，我希望进入设置时音乐继续播放，以便改设置不打断听歌。
11. 作为桌面端用户，我希望设置分通用/资料库/音乐源/应用四组，以便按心智模型找项。
12. 作为桌面端用户，我希望外观设置能选跟随系统/浅色/深色并即时生效，以便夜间不刺眼。
13. 作为桌面端用户，我希望缓存页用一条主行说明已用容量与上限，以便不用在四组数字里对账。
14. 作为桌面端用户，我希望缓存页仍能清理全部与按类型清理，以便照旧管理磁盘。
15. 作为桌面端用户，我希望下载页能设置保存目录、并发数与命名规则，以便照旧管理下载。
16. 作为桌面端用户，我希望「直连状态」一屏列出每个音乐源的可用性，以便判断换源预期。
17. 作为桌面端用户，我希望「第三方解析源」仍能订阅、启停、排序、看近期成功率，以便维护兜底链路。
18. 作为桌面端用户，我希望代理与 TLS 指纹伪装收进「网络」页的两个设置行，以便不占导航。
19. 作为桌面端用户，我希望「检查更新」仍能显示版本、检查、下载与安装，以便更新路径不变。
20. 作为桌面端用户，我希望「关于」里能看到版本、仓库链接与开源许可，以便查证来源。
21. 作为桌面端用户，我希望开发者模式仍在「关于」的高级区域里可开启，开启后出现诊断页，以便排障入口不丢。
22. 作为桌面端用户，我希望设置/通用列表行高 44、资料库歌曲行高 46（原型 92/2）、分组卡片圆角一致、行间只用发丝线，以便界面有统一节奏。
23. 作为桌面端用户，我希望选中态用表面明度差表达，品牌蓝只出现在主操作上，以便界面不花。
24. 作为桌面端用户，我希望标题栏、侧栏、播放栏是半透明材质，其余区域纯色，以便层级稳定且滚动不掉帧。
25. 作为桌面端用户，我希望 120/200ms 的物理缓动贯穿所有交互，以便操作跟手。
26. 作为桌面端用户，我希望数字使用等宽数字，以便时间与容量不跳动。
27. 作为桌面端用户，我希望全屏播放器用封面取色生成环境光，以便播放状态有辨识度。
28. 作为桌面端用户，我希望浅色与深色都经过对比度检查（正文 ≥ 4.5:1），以便两种主题都可用。
29. 作为桌面端用户，我希望窗口小于 1024 宽时布局不被压垮，以便不出现错位。
30. 作为桌面端用户，我希望搜索、换源弹层、右键菜单、排序、拖拽、虚拟滚动全部保留，以便核心工作流不变。
31. 作为桌面端用户，我希望空态、加载态、错误态都有明确文案与可操作按钮，以便知道下一步做什么。
32. 作为桌面端用户，我希望键盘可以遍历所有可交互元素并看见焦点环，以便不用鼠标也能操作。
33. 作为桌面端用户，我希望启动更快、内存更省，以便老机器也顺滑。
34. 作为桌面端用户，我希望这次升级不改变我的歌单、收藏、播放历史与设置项，以便升级后数据不丢。
35. 作为维护者，我希望组件只有一套，以便改一次样式全站生效。
36. 作为维护者，我希望 design-lint 严格覆盖桌面端且没有存量白名单，以便回归不会悄悄长回来。

## Implementation Decisions

- **组件库**：移除 `antd` 依赖（现用 13 个组件、56 处引用：message 18、Modal 11、Button 7、Tag 5、Switch 4、Typography 3、Input 2，Progress/Alert/Checkbox/Table 各 1），全部由自建原语承接。Toast 取代 message，Dialog 取代 Modal（原生 `<dialog>` + 焦点陷阱 + ESC 关闭），Table 的唯一样式改为网格列表。移除后同时删除 `ConfigProvider` 主题桥与 `ANTD_ACCENT` 常量。
- **布局原语**：`Group`（12px 圆角、无边框、`--card` 表面）、`Section`（组标题 12/600 + 行 + 11px 脚注）、`Row`（44px 高、左右 14、发丝线左内缩 47）。所有设置与列表页只用这三层表达层级，禁再用 Card/Divider 拼。
- **Token**：沿用两层架构（Primitive → Semantic），新增材质、发丝线、选中填充、三档灰阶与四档字阶 token。强调色保持 `#2F5FD0`（暗 `#3D7BD9`）；语义色沿用现有成功/警告/危险色。材质 `backdrop-filter: blur(24px) saturate(180%)` 仅用于标题栏、侧栏、播放栏与浮层；虚拟滚动行内禁用。
- **导航**：侧栏 6 项（推荐 / 发现 / 资料库 / 我喜欢的音乐 / 最近播放 / 我的歌单）；设置是标题栏右列的文字按钮。资料库页内分段：歌曲 · 专辑 · 歌手 · 下载 · 本地（原型定稿，默认「歌曲」）。队列入口 = 播放栏按钮 + 全屏播放器队列页。
- **设置**：独立路由的全屏视图，进入即隐藏侧栏与播放栏，保留标题栏；左上返回按钮与 ESC 都可退出；播放不中断。分组：通用（外观、播放）/ 资料库（缓存、下载）/ 音乐源（直连状态、第三方解析源、网络）；「更新」「关于」钉在导航底部固定区。无 section 参数时默认落「缓存」（原型默认页）。开发者模式开启后追加「诊断」页；代理与 TLS 指纹伪装合并进「网络」。
- **窗口**：最小尺寸 1024×720，不做响应式断点与缩放。
- **门禁**：`design-lint` 覆盖 `src/renderer` 与移动端现有范围，四条硬规则——禁止 `style={{ … }}`（仅允许 `style={{ '--x': value }}` 传自定义属性）、禁止颜色字面量、禁止 `antd` 引入、禁止字号/字重/圆角字面量（token 文件豁免）；无存量黑名单。删除零引用文件（`CustomDropdown`、`useDiscoverData`）。
- **数据不变**：不改既有 store 数据模型、core 播放链路与既有持久化键；仅新增原型明确要求的缓存容量配置（`cacheLimitMb` / `cacheAutoClean`）与外观偏好（`mplayer.appearance`）两个新键。升级后设置、歌单、收藏保持原位。
- **交付**：单分支 `feat/ui-redesign-1.9.0`、单 PR、PR 内按批次 commit；版本号在最后一批改为 1.9.0。

## Testing Decisions

- **好的测试**：只断言用户可见的外部行为——可访问名、可见文本、焦点顺序、键盘操作、状态切换；不断言 className、内联样式或组件内部结构。
- **接缝**（由高到低，尽量复用既有接缝）：
  1. 原语层：每个原语一个渲染测试，覆盖默认态、禁用态、键盘与焦点可见性。单一接缝，全站组件共用。
  2. 页面层：沿用现有 renderer 的 RTL 页面测试模式（`window.electronAPI` stub 已在 setup 里），断言「每个入口存在且可触发」。
  3. 端到端：真实 Electron 进程截图 + 关键路径点击（运行时验收 skill），作为 PR 证据。
  4. 静态门禁：design-lint 与 typecheck 是第四道接缝，机械覆盖全量代码。
- **先例**：`src/renderer/__tests__/` 下 60 个页面测试、`src/renderer/__tests__/setup.ts` 的 electronAPI stub、`scripts/design-lint.mjs`。

## Out of Scope

- 移动端任何改动（下个版本单独跟）。
- core 播放链路、跳歌护栏、随机序列、换源候选逻辑。
- 新增功能（原型 Prototype Geometry 注明的控件除外：缓存容量/自动清理、外观偏好、全屏播放器队列与详情）。
- 国际化与多语言。
- 安装包签名、更新通道、发布流水线。

## Further Notes

- **功能等价性是硬约束**：PR 必须附功能矩阵（每个旧入口 → 新位置 → 验收方式），逐条勾掉；截图证据进 PR 正文，不入库。
- 原型与最终实现允许有差距，但 token 数值、行高、圆角、材质范围以本规格为准。
- 期望收益：主 chunk 从 1016KB（gzip 395KB）显著下降；移除 cssinjs 运行时样式注入；依赖从 50 个减到 49 个并去掉 57.5MB 的 `node_modules/antd`。
