# MPlayer 设置页/下载页 UI 精修 + 桌面端深色模式 + token 全面清理 — 规格

> 日期：2026-08-23 · 分支：`feat/settings-download-ui-refine` · 来源：grilling 设计会话收敛，to-spec 留痕

## Problem Statement

移动端设置页卡片过多（8 张堆叠、部分信息过载），下载页（本地歌曲 tab）空态时「保存位置」被一起垂直居中、布局异常；桌面端设置页 token 混乱（旧别名 `--content-bg`/`--border-color` 等 + 魔法色值散落），且不支持深色模式，与移动端（已有 light/dark 双主题）不对称。用户希望设置页更清爽、下载页布局正确、桌面端补齐深浅色切换且配色统一可维护。

## Solution

移动端设置页精简为 5 张卡片（移除代理/播放日志/关于），外观改为一体分段控件，直连设置简化为「直连状态」清单；下载页修复空态布局、保存位置卡片化、下载中显示进度条；下载 tab 改名为「本地歌曲」。桌面端新增「跟随系统/浅色/深色」三态切换，全 renderer token 统一（去旧别名与魔法色），深色模式下全应用（含设置页、弹窗、antd 组件）自动适配，深色 token 值以移动端 `darkColors` 为镜像基准。

## User Stories

1. 作为移动端用户，我希望外观卡只保留「跟随系统/浅色/深色」三个按钮且没有多余说明文字，以便快速选择主题。
2. 作为移动端用户，我希望外观的三个按钮是排版干净的一体分段控件，以便视觉更精致。
3. 作为移动端用户，我希望直连设置只展示每个音乐源的直连状态（圆点 + 文案），不需要再配置 auto/仅直连，以便一眼看出哪些源直连可用。
4. 作为移动端用户，我希望代理设置入口从设置页移除（手机默认不用代理），以便设置页更简洁、避免误配。
5. 作为移动端用户，我希望播放日志不再占用设置页卡片，以便只看到常用设置。
6. 作为移动端用户，我希望「关于」不再以卡片形式占用空间，以便设置页更紧凑。
7. 作为移动端用户，我希望缓存管理能显示已用容量进度条，以便了解缓存占用情况。
8. 作为移动端用户，我希望下载页在没有任务时「保存位置」固定在顶部、空态在中央居中，以便布局正常不悬空。
9. 作为移动端用户，我希望下载页「保存位置」是明显可点的卡片（带 chevron），以便知道可以更换目录。
10. 作为移动端用户，我希望下载中的歌曲显示进度条，以便直观看到下载进度。
11. 作为移动端用户，我希望下载 tab 改名为「本地歌曲」，以便名称与内容一致。
12. 作为桌面端用户，我希望设置页出现「外观」三态切换（跟随系统/浅色/深色），以便控制主题。
13. 作为桌面端用户，我希望深色模式下整个应用（设置页、各页面、弹窗、antd 组件）配色正确，以便夜间使用不刺眼。
14. 作为桌面端用户，我希望主题选择被持久化，以便重启应用后保持。
15. 作为桌面端用户，我希望「跟随系统」模式随操作系统深浅色自动切换。
16. 作为开发者，我希望 renderer 不再残留旧别名与魔法色值，以便主题可预测、深色模式不会漏色。
17. 作为开发者，我希望音乐源品牌色只有一个来源，以便改色只改一处。
18. 作为开发者，我希望桌面端主题解析是纯模块、可单测，以便回归有保障。

## Implementation Decisions

- 移动端设置页：
  - 外观卡：移除说明文案；三态按钮合并为无缝分段控件（容器底色 + 内嵌激活段，深浅色下均可读，激活态用 accent/表面色区分）。
  - 直连设置 → 直连状态：每源一行 = 状态圆点（可用=成功色 / 未实现=中性色）+ 源名 + 状态文案；移除 auto/direct 分段控件及页面内的调用。core 的 sourceModes 状态与持久化保持不变（默认 auto，后续可清理）。
  - 代理设置卡片从设置页移除；core/store 的代理逻辑本次不动，留待后续单独清理。
  - 播放日志卡片、关于卡片整卡移除（版本号不再展示）。
  - 缓存管理卡：统计行下方加用量条（对齐桌面 100MB 口径，>90% 显示危险色）。
  - tier3、检查更新两张卡保持现状。
- 移动端下载页：
  - 修空态布局：保存位置 header 常驻顶部，空态独立垂直居中（不再共处同一 flex 容器被一起居中）。
  - 「保存位置」改为卡片式（surface 底 + 圆角 + chevron 提示可点）。
  - 下载中行加细进度条（基于 `progress` 0–100；未知总量按已收字节估算）。
  - 行结构与全 App 列表惯例（封面占位 + 主副标题 + 状态列）对齐；空态复用共享 EmptyState 组件。
- 移动端 tab 改名：下载 → 本地歌曲（仅 label 与页面文案；路由路径与持久化 key 不变）。
- 桌面端主题：
  - `global.css` 新增深色语义 token 集（值对齐移动端 `darkColors`），通过 `prefers-color-scheme` + `data-theme` 覆盖实现三态（跟随系统/浅色/深色）。
  - 设置页新增「外观」section 与导航项承载三态切换；主题解析做成纯模块：输入 `{ 存储模式, 系统偏好 }` → 输出 `{ 生效模式, isDark, data-theme 值 }`；持久化在 renderer 层。
  - antd `ConfigProvider` 随主题切换 `darkAlgorithm` 与 `colorPrimary`。
  - 数据可视化色（缓存构成分类色）与更新状态色语义化：引入带深色变体的语义 token（成功/危险/警告/信息等）替换魔法色。
- token 清理：
  - 全 renderer 旧别名（`--content-bg`/`--border-color`/`--divider-color`/`--bg-color`/`--accent-color`/`--hover-bg` 等 1:1 别名）替换为对应语义 token；替换完成后移除别名块。
  - 伪 token 魔法色（`--primary-color`/`--primary-hover`）映射到真实语义色。
  - 音乐源品牌色收敛为单一常量模块，各组件（源徽章/源切换/顶栏/链接预览）统一引用。
  - `DownloadProgressModal` 的魔法色（`#52c41a`/`#ff4d4f`）→ 语义 token。
- 桌面端主题解析纯模块是本次唯一新增的可自动化逻辑缝。

## Testing Decisions

- 只测外部行为、不测实现细节：主题解析模块以 `{ mode, systemPrefersDark }` 为输入，断言输出 `{ effectiveMode, isDark, dataTheme }` 及持久化读写。
- 被测模块：桌面端主题解析（renderer 层，jsdom 环境；先例 `src/renderer/__tests__/downloadStore.test.ts`）。
- 移动端不新增自动化缝（纯布局/样式改动，RN 组件测试缝收益低）：按项目惯例走真机验收——深色三态切换、下载页空态与进度条、设置页精简后的布局。
- 不做 e2e（已确认排除）。

## Out of Scope

- 桌面端设置页布局重构（两栏「左导航 + 右滚动」结构保持不动）。
- 移动端代理逻辑的代码清理（本次只移除 UI 入口，后续单独清理）。
- 移动端全 App 视觉重设计（本次只做设置页 + 下载页）。
- 桌面端真实下载管理页（`/download` 目前是 ComingSoon 占位 → 做真实页属新功能）。
- 为移动端引入 RN 组件自动化测试缝。
- 字体/排版体系更换（保留 Apple HIG 蓝调体系，Q2=A 精修不换皮）。
- 全 renderer 清理之外的任何重构。
