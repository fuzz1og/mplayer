# 移动端发现页视觉改版 + 全局 token 对齐 — 规格

> 日期：2026-11-16 · 分支：`claude/ui-ux-page-review-de756f` · 来源：UI/UX 审查后的设计会话收敛，to-spec 留痕
> 状态：已实施（2026-11-16，未提交）。方向板：`design/mobile-discover-axtc.html`（会话资产，不入库）；对照 `design/mobile-visual-directions.html`。
> 决策：发现页结构重做，**主题色沿用现有蓝调**（应用图标已定，2026-11-16 真机验收后确认不改色）；发现页不重复可见页名；性能优先，不做滚动区实时模糊。桌面端本次不动。

## Problem Statement

移动端发现页目前是“深色 iOS 卡片 + 蓝色强调”的通用组合：四条榜单平铺（网易云热歌/QQ 热歌/网易云新歌/QQ 新歌）、一级分段 + 二级分类并存、内容没有焦点，页面很长但缺少“今天听什么”的引导。其他屏幕的间距、字号、圆角、选中态各写各的，读屏标签、键盘避让、空/错态等小问题也没有收口。

用户要的不是全 App 重做，而是：**发现页做出新的视觉身份；其他屏幕只做 token、边距、字号、圆角统一和小 bug 对齐；桌面端后续单独做细节 pass。**

## Solution

- 视觉方向：沿用现有蓝色双主题与 `palette.blue*` 强调色，不换主题色；只保留 C 的封面光思路（今日焦点 hero 用封面图 + 静态深色渐变），图标默认中性，只有 active tab、播放键、进度、主按钮使用强调色。
- 发现页去掉内容区可见页头：顶部只保留「排行榜 / 新碟 / 歌单 / 歌手」内容 tab + 来源切换；页名只保留在底部 tab、路由标题和读屏 h1。
- 发现页结构改为：今日焦点 hero + 当前来源的热歌/新歌两个 section；新碟、歌单、歌手沿用现有数据面，统一卡片与间距。
- 其他屏幕只做 token 替换、间距/字号/圆角统一，以及已确认的小 bug；不改导航与信息架构。
- 性能：不引入实时模糊、逐帧取色、新原生模块或新依赖；用静态渐变、一次性封面色、半透明实色表面。目标中端 Android 60fps。

## User Stories

1. 作为移动端用户，我希望发现页顶部不要重复印「发现」两个大字，以便内容直接开始。
2. 作为移动端用户，我希望发现页用一行内容 tab 在排行榜/新碟/歌单/歌手之间切换，以便快速换看法。
3. 作为移动端用户，我希望来源切换只影响发现页内容，不影响全局搜索来源。
4. 作为移动端用户，我希望排行榜有一个「今日焦点」，直接看到当前来源的热歌榜首曲并播放，以便不用先滚列表。
5. 作为移动端用户，我希望热歌榜和新歌榜各有清晰的榜单列表和「查看全部」，以便快速进入完整榜单。
6. 作为移动端用户，我希望新碟 tab 有编辑推荐和地区筛选，并能在网格里浏览新碟，以便发现新专辑。
7. 作为移动端用户，我希望歌单和歌手 tab 保持分类筛选与网格，但卡片、间距、字号与全 App 一致。
8. 作为移动端用户，我希望发现页在浅色和深色主题下都清晰可读，以便夜间使用不刺眼。
9. 作为移动端用户，我希望滚动发现页时不掉帧，以便低端 Android 也顺滑。
10. 作为移动端用户，我希望其他页面的边距、字号、圆角、选中态与发现页同一套规则，以便切换页面不觉得是另一个 App。
11. 作为移动端用户，我希望图标按钮有读屏名称、选中态能被读屏识别，以便用 VoiceOver/TalkBack 操作。
12. 作为移动端用户，我希望搜索、新建歌单、加入歌单等输入场景不被键盘挡住，以便小屏也能完成操作。
13. 作为移动端用户，我希望空态和失败态有明确区别，并且失败可以重试，以便知道下一步做什么。
14. 作为维护者，我希望颜色/字号/间距/圆角只从 token 取，以便改一次全 App 生效。
15. 作为维护者，我希望发现页的骨架与真实布局同形，以便加载完成不跳版。
16. 作为评审者，我希望发现页四个 tab、双主题、真机截图和帧率数据作为验收证据。

## Implementation Decisions

### 1. Token 基座（`packages/mobile/theme/tokens.ts`）

- 颜色：**沿用现有蓝调双主题**，不换主题色。`accent` 保持浅色 `palette.blue500` / 深色 `palette.blue350`，背景/文字/边框/输入框全部沿用原值；`bgBase` 浅色 `#F2F2F7`、深色 `#000000`。
- `textTertiary` 保持“装饰/提示”低对比语义，不用于有效正文；有效 meta 改用 `textSecondary`（不改色值）。
- 强调色只用于 active / 播放 / 进度 / 主按钮；选中列表用表面明度差（`bgHover`/`bgActive`），不用强调色铺底。
- `textInverse` 保持原值：浅色白字，深色 `palette.gray900`。
- 语义色沿用现有 `dangerText/warningText/successText` 纪律；源品牌色只出现在 `SourceBadge`。
- 字体：`largeTitle 24/700`、`titleLg 20/700`、`title 17/700`、`sectionHeader 17/700`、`body 15/500`、`subhead 14/500`、`footnote 13/400`、`caption 12/400`、`micro 10/600`；时间/排名/计数一律 `tabular-nums`。
- 间距：页面沟槽 16、区块间距 24、网格间距 12；歌曲行沿用 `SONG_ROW`（#416 单一事实源，封面 44 / 行高约 64），本轮不缩行——缩行要同步改所有列表页与骨架，超出「对齐」范围。圆角：控件 8、卡片 12、hero 16、sheet 12–20。
- 阴影保持克制；深色主题主要靠表面明度差，不靠阴影。

### 2. 发现页信息架构

- **顶部**：一行内容 tab（排行榜 / 新碟 / 歌单 / 歌手）+ 右侧来源 chip（网易云 / QQ，打开 BottomSheet）。无可见页头；保留视觉隐藏的 h1「发现」。
- **排行榜**：今日焦点 hero（当前来源热歌榜首曲：封面图 + 静态深色渐变 + 歌名/歌手 + 播放）；下方「热歌榜」「新歌榜」两个 section，各 10 行（名次 + 封面 + 歌名/歌手 + 时长），行点击播放，section 头可进完整榜单。
- **新碟**：编辑推荐 hero（第一张新碟，点击进专辑详情）+ 地区分类（全部/华语/欧美/韩国/日本）+ 三列网格 + 查看全部；加载/空/错态同形。
- **歌单**：分类 chips + 两列歌单网格 + 加载更多；沿用现有数据与详情路由。
- **歌手**：分类 chips + 三列圆形歌手网格；沿用现有数据与详情路由。
- **切换**：tab 切换 200ms 淡入 + 8px 上移；不做横向分页、不保留 4 个页面同时挂载；来源切换只重载当前 tab 的数据（沿用 store 缓存/TTL）。
- **错误/空态**：每个 tab 独立；失败给文案 + 重试；空态给可行动入口（重试 / 查看全部）。

### 3. 其他屏幕：只做对齐

- **不再在 tab 内容区重复可见页名**：底部 tab / 原生 header / 路由标题已经承担身份；歌单页的「我的歌单」大标题与组标签重复时只保留一个。非 tab 页面（歌单/专辑/歌手详情）保留自己的 hero 标题。
- 全量替换硬编码颜色、字号、圆角、间距为 token / `textVariants`。
- 列表行沿用 `SONG_ROW` 既有度量；卡片统一 12px 圆角、无大阴影；筛选控件统一为 `TextTabs` / `SegmentedTabs` 两套之一，不再新增第三套。
- 选中态统一表面明度差；播放态才用强调色。
- 本次必须闭环的小 bug：
  - `ScalePress` 补 `accessibilityRole` / `accessibilityState` / `accessibilityLabel` 透传；图标按钮补读屏名称；分段/tab 播报选中态。
  - `PlayerOverlay` 补 modal 语义、Android 返回关闭、浅色前景对比。
  - 搜索列表 `keyboardShouldPersistTaps="handled"`；新建歌单/重命名/加入歌单/BottomSheet 补键盘避让。
  - 推荐页「播放全部」用可见批次入队，不再把 100 首池入队。
  - 歌手详情歌曲失败、发现歌单失败/分页失败补错误态 + 重试。
  - `BottomSafePlayerBar` 首次播放前隐藏；`CollapsingHero` 封面阶段状态栏恒白字、折叠出实心导航栏后按 `isDark` 取深浅，navRight 补可读背景。
  - 下载删除热区 ≥44、补标签；空态补可行动入口。

### 4. 性能约束（硬约束）

- 禁止在滚动内容、列表行、全屏背景上使用实时 `BlurView` / `backdrop-filter`。
- 禁止逐帧从封面取色；封面色只在图片加载完成时取一次并缓存，失败回落到预置渐变。
- 玻璃观感用「半透明实色 + 1px 内高光 + 静态渐变」实现；不引入新原生模块或依赖。
- 小面积静态 chrome（tab bar / 迷你播放栏）如需 blur，仅 iOS 开启、Android 实色兜底；默认关闭。
- 动画只动 `transform` / `opacity`，`useNativeDriver: true`；不做布局动画；`prefers-reduced-motion` / `AccessibilityInfo` 下退化为淡入。
- 验收：中端 Android 60fps；`npm run mobile:frame-stats` 无连续掉帧；发现页滚动、tab 切换、hero 图片加载各测一轮。

### 5. 主题

- 双主题颜色沿用现有蓝色体系，不在本次改版中更换；浅色仍为灰底白卡片，深色仍为黑底灰卡片。
- 两套 token 必须一一对应；新增/改名 token 时同步 `theme/README.md` 映射表。
- 源品牌色只在 `SourceBadge`；文字徽章走 `sourceText` 双主题变体。

## Testing Decisions

- 只测用户可观察行为：发现页 tab/来源切换、点歌建队列、空/错态重试、tab 选中态可访问名。
- 单元：token 对比度（accent 对四层表面 ≥4.5、textSecondary ≥4.5、skeleton 可见度下限）；发现页 tab/source 状态；推荐页“播放全部”队列语义。
- 组件：`DiscoverTabs` 的四个 tab、来源 chip 打开/选择、错误/空态；`SongRow` 的读屏标签与选中态。
- 真机：发现页四 tab + 双主题截图；播放器、搜索、歌单详情、设置各一张；VoiceOver/TalkBack 走查；`mobile:frame-stats`。
- 静态门禁：`npm run design-lint`、`npm run typecheck:mobile`、`npm run test:run`。不新增 e2e。

## Out of Scope

- 桌面端任何视觉改动（后续单独细节 pass）。
- 底部 tab / 路由 / 导航层级调整。
- core 播放链、源路由、搜索/推荐数据逻辑。
- 实时模糊、新原生模块、新第三方依赖。
- 新增音乐内容能力（MV、播客等）。
- 全屏播放器的结构重做；本轮只做 token、强调色、对比度对齐。
