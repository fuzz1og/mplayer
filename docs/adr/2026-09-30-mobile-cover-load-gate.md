# 移动端封面在飞闸门与专辑列表窗口化

- 日期：2026-09-30 · 状态：已接受 · 关联：**#496**（本决策票）、#417（歌手页专辑面）、#406（专辑页 UI）
- 依据：ADR `2026-09-26-outbound-request-governance.md`（决策 5 把图片排除在出网闸门之外）、ADR `2026-09-29-queue-virtualized-sortable-list.md`（同一「挂载副作用」口径）

## 背景

1. ADR `2026-09-26-outbound-request-governance.md` 决策 5 把**图片**显式排除在 core 出网闸门之外：
   「两端都是原生 `Image` 直接拉 CDN，不过 core」。当时这是如实记录，不是没有代价。
2. #417 把移动端歌手页的专辑分区从 20 张提到 **100 张**，而横滑条仍是**普通 `ScrollView`**：
   一进歌手页 = 100 个 `<Image>` 同时挂载 = 100 条并发图片请求。
3. 同票新增的专辑时间线页 `PAGE_SIZE = 100`，且**没接** `listWindowProps`（RN 默认 `windowSize: 21`），
   3 列网格同样整页铺开。
4. 全仓封面 `<Image>` 没有任何在飞上限：模块挂载 = 立刻发请求，挂多少发多少。
5. 实测后果（#496）：一进这类歌手页，上游限流 → 后来连**已经发出**的图也卡住拿不到。

「列表规模」把第 1 条那条缝放大了：内容数据有闸门、封面图片没有。

## 决策

1. **移动端封面补一层在飞闸门。** 新增 `packages/mobile/services/coverLoadGate.ts`：FIFO + 固定上限
   （起步 6，与 core 出网闸门的全局上限同量级）+ 每槽 20s 墙钟（持有者不回调时强制归还、
   放行队列）。**不拒绝、不丢请求**——形态与 `coverSearchSlot` / tier3 `MAX_TIER3_IN_FLIGHT` 一致。
2. **封面渲染统一走 `components/LazyCover.tsx`**：先拿到槽位再挂 `<Image>`；
   `onLoad` / `onError` / 卸载三处归还槽位（`release()` 幂等）。
   首屏关键封面（折叠 Hero / 迷你播放栏 / 全屏播放器）**不过闸**：一屏只有一张，过闸只会给首帧加排队。
3. **「数据页大小」与「渲染窗口」分开看。** 歌手页横滑条的 `limit=100` 是**数据**口径，不是渲染许可：
   横滑条改**横向 FlatList**（窗口 3 屏）；时间线页 `PAGE_SIZE` 100→30 并接 `listWindowProps`。
4. **闸门只装在移动端。** 桌面端封面由 Chromium 网络栈与渲染进程管，页大小 30、带宽量级不同，
   不在本决策范围。

## 备选与否决

- **只做虚拟化、不加闸门**：否决。窗口化能减少挂载数，但 `windowSize` 以「屏」为单位
  （7 屏 × 每屏数张 = 几十张封面在飞），对手机上行仍然过量；「在飞上限」这件事必须有个落点。
- **把图片并进 core `transport` 的闸门**：否决。图片并不过 core（原生 `Image` 直连 CDN）；
  要走 core 就得自己下载字节再喂给 `Image`，等于自建图片管线（缓存/解码/内存全归我们），
  成本与收益不成比例。
- **闸门上限取 3（与 tier3 K 同档）**：否决。封面是纯装饰且请求短，3 会让整屏出图明显变慢；
  6 与 core 全局上限同档是保守起点，等有指标再谈调参。
- **给 `LazyCover` 加 `priority` 参数**：本轮不做。没有调用方需要（关键封面本来就不经过它）；
  真出现「首屏第一张必须抢跑」再加。

## 后果

- 进 243 张的歌手页：并发封面请求从「一次 100 条」变为「同时在飞 ≤ 6」，其余 FIFO 排队。
- **代价：图会一张张出现，而不是整屏一起闪出。** 这是有意的——「整屏一起闪出」的前提正是并发无上限。
- 槽位墙钟 20s 是最坏情况的护栏；正常路径由 `onLoad` / `onError` 释放。若某宿主实现不回调这两个
  事件，最坏是并发短暂超限，而不是整屏封面永久停在占位。
- 闸门统计（在飞 / 排队 / 峰值 / 累计）已暴露为 `stats()`，但**本轮不接设置页诊断区**——
  与 ADR 2026-09-26 决策 6 的「先有指标再调参」同一取向，接线留到有实际调参需求时。
- 本决策**部分收回** ADR `2026-09-26-outbound-request-governance.md` 决策 5 中「图片不受闸门约束」这一条，
  收回范围仅限移动端封面；core 出网闸门本身不变。
- **未解决**：`ContentCache` 仍是**同步**接口（core 侧），封面/内容元数据无法写进移动端磁盘 L2
  （`CacheKernel` 是异步的）。那是另一条决策，本票不碰。
