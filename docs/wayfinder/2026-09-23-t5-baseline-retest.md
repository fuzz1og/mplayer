## 0. 一页结论

1. **冷启真实分布从「两极」变成「一侧命中」**：Flow C（冷启、用户真实配置、22 首）**直连 7（32%）/ tier3 14（64%）/ 失败 1（4.5%）**；基线为 5（23%）/ 11（50%）/ **6（27%）**。
2. **总时延 P50 3120ms → 1082ms（−65%）、P90 6145ms → 2124ms（−65%）、max 6160ms → 2644ms**。基线里占据主导的「6.1s 后失败」这一支基本消失。
3. **QQ 子样本 6/6 从全灭变全通**：6 首全部经 tier3（C1）拿到 URL，耗时 953–1107ms（基线 6/6 失败、恒 ~6.1s）。受控实验里「真实顺序 → 6077ms 空」变成「真实顺序 → 1087ms 命中」。
4. **唯一的失败项是硬墙边界的偶发**：kugou《我不难过》一次 2001ms 超时失败；同曲重跑 6 次 5 次成功（679–847ms）、1 次 1989ms（距 2s 单源硬墙仅 11ms）。**不是稳定的 6/22 结构性失败**。
5. **护栏确实在生效，且交付候选全部有内容级证据**：22 首里 tier3 交付 14 次，护栏等级**全部是 `audio-header`（L2 音频头时长证据）**，没有一例退到「仅歌名歌手（L4）」或「仅 source 声明（L5）」。跨源 gate 正常：C1（qq）被跳过 27 次、C2（netease）被跳过 24 次。
6. **#362 的交付口径修正生效**：会话末 `hits == resolved`（C1 14/14、C3 18/18），`discarded` 不再把迟到命中算成命中——基线「hits=17 而实际 0 交付」的误导消失。
7. **预取「天然 0 等待」只在完整版成立**：预取命中 11/22（50%），其中只有 5 首（23%）是缓存直链 0.00ms 直接播；**6 首是试听版（nonFull）**，播放时仍要进 tier3，实测 1.9–2.0s（#363 评论预言的「预取命中不再天然 0 等待」被证实）。
8. **HTTP 层干净了**：181 次尝试（基线 353）、**0 次 ECONNRESET**（基线 73）、单次最大 **2070ms**（基线 12996ms）——慢源与坏源不再在链上。
9. **归因诚实说明**：上述改善里，**配置变化（移除 4 个源，其中 S1/S2/S7 是吃满预算的慢源；单源超时显式设成 2s）是最主要的因素**；#361/#365 的代码贡献（单源 2s 硬墙、交付统计、guard 字段）在本样本里体现为「边界封顶与可观测性」，而不是主要提速来源。

### 2.6 护栏证据等级（#361）

- 22 首里 tier3 交付 14 次，**guard 分布：`audio-header`（L2）×14，其余等级 0**。

## 4. 对 #363（埋点实现）的直接输入

本次重测用的仍是**临时探针**，不是生产 trace；它验证了 #363 定案的 trace 字段确实能回答这些问题，并给出实现时的三个必测口径：

1. **`prefetchHit` 必须与 `nonFull` 联合**：完整版预取命中是 0.00ms，但试听版预取命中要进 tier3（1.9–2.0s）。trace 若只记「预取命中」会把两种语义混在一起。
2. **tier3 腿必须逐候选记 `resolveMs + validateMs`**：本次每个交付候选都走了 L2 音频头取证（64KB Range / 头解析）；把取证成本并入解析腿会虚高解析耗时。护栏拒绝 2 次也必须作为候选级 outcome 记录。
3. **`layer` 与 `via/guard` 分开记**：`layer` 是用户可感知的「命中层级」，`via` 是来源腿、`guard` 是证据等级；本次「14 交付全 L2」若不单独记 guard，就无法审计护栏是否退化成 L5 信任。
4. `tier3Stats` 还需补每源 `ms`（本次只能靠外挂探针量）；`delivered/discarded/guardRejected` 已由 #362/#361 落地，可复用。

**建议优先级更新**：
1. **单源硬墙的边界**：2s 对「搜索 + 解析」两步源偏紧（C3 1119ms 命中、偶发贴墙）；可考虑按源类型给 search-then-resolve 稍宽上限，或对「已进入候选解析」的源延长尾部。
2. **soda 直连**：唯一仍 >300ms 的直连 P50（844ms），值得单独看。
3. 预取覆盖率从 23% 提到 50%（本次），但**其中一半是试听版**，真正 0 等待仍只有 23%——「让探测带 tier3 + 只有完整版才写预取」值得评估。
4. 失败率目标 ≤1% 需以 ≥100 首样本复核后再定（当前 22 首，1 次失败即 4.5%）。
