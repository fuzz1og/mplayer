# MPlayer v1.8.8

22 天、93 条提交（不含 merge 与本 bump）。这一版的主线是**更新流程重做**与**随机播放链路收口**。

## 🚀 版本亮点

- **进入即检查更新**：双端启动后自动检查一次（失败一律静默，不打扰）。桌面发现新版直接后台静默下载，下完弹应用内确认框「立即安装并重启」，一次询问、不再冒出安装器第二句「应用正在运行」；左下「设置」旁挂更新徽标。移动端弹窗可「叉掉」（按版本号记忽略，下个版本仍弹）或跳浏览器下载。
- **随机播放不再错歌**：修掉四类缺陷——对齐作用域（把原生预取窗口当权威成员集会永久截断随机序）、歌曲身份、游标落点、双份状态。队列的四份数据（成员序 / 当前下标 / 随机序 / 游标）此前由 14 个 action 各写一遍三连，漏一格就静默脱节；现在收敛到 `planQueueState` 单一入口 + 落盘单一出口。
- **队尾不再原地重播**：窗口饱和到队列最后一首时，不再把末首当成「下一首」重播一遍。
- **系统对话框记住上次目录**：选下载目录、添加本地音乐、导入 tier3 清单、导出诊断各自记各自的，互不污染（Electron 43 起未传 `defaultPath` 会固定落 Downloads 且 OS 不再记忆）。
- **直连链路三处静默失效修复**：可播 URL 的编码归一回到解析链唯一出口（且不再被孤代理炸掉）、汽水换源歌先剥源前缀再进端点、网易按 songId 直取歌词先剥前缀（修复移动端歌词空串）。

## ✨ 变更详情

### Desktop（Electron）
- 进入即检查更新 + 后台静默下载 + 应用内确认后退出安装；设置页保留手动检查与浏览器下载兜底（#579）
- 系统对话框记忆上次使用的目录，按用途分键（#670）
- 队列页在重复 id 的队列下删错成员（#660 / #639 收口）
- 播放栏收藏按钮订阅 store 方法，导致心形状态不重渲染（#620）
- 队列状态转移补齐 `reorder-shuffle` / `clear` 两个变体；planner 终止类变体改名 `clear`，避免与「停播」撞名
- 删除孤儿 `playlist:addSong` 通道与第二份容量实现（#610）
- Electron 41.10.7 → 44.9.3：清掉 audit 里唯一进产物的 high；**macOS 下限随之变为 13 (Ventura)**，更早系统装上也无法运行（#658）
- 安装器图标上下颠倒（ICO 的 BMP 条目改为 bottom-up 写行）（#626）

### Mobile（Expo / React Native）
- 进入即检查更新弹窗，按版本号记「已忽略」（#579）
- 窗口饱和到队尾时不再把末首原地重播（T8 续播守卫，#650）
- 内嵌封面按字节上限自适应降档（640 → 320），且降档失败不丢已成功的那一档（#575）
- 落盘快照保留 per-item 请求头，restore 段不再裸奔（#606）
- Android 原生开始发每源 UA / Referer，请求头出 core 单点（#592）
- 终局闩收成 `ExhaustionLatch`，置位 / 清除 / 查询单一落点（#609）
- 原生补窗结算判定抽成纯函数，并补 Android 原生播放模块的 JUnit 行为测试源集（#640）

### 多源与解析（core，双端共享）
- 可播 URL 的编码归一落在解析链唯一出口，一处覆盖四条腿与预取命中；孤代理不再炸掉归一（#622 / #635）
- 汽水链路先剥源前缀再进端点，换源歌不再静默降级（#629）
- 网易 songId 直取歌词先剥源前缀，修复移动端空串（#623）
- 可播版本解析上收 core、播放地址解析提出模块，桌面四处页面共用一份（#639 C2/C3）
- 取词决策收敛到 core `planLyricsFetch`，下载侧与播放侧消费同一个单点（#608）
- M4A 标签口径收敛为「只承诺 MP3」，新增 `planAudioTagging` 单点（#607）
- 解析链四条腿共用 `runWithLegWall`；导入 deps 装配下沉 `importDepsFor`（#593 / #594）

### CI / 构建 / 工程
- 新增 `comment-gate`：注释块内容行 >3 即拦，并清理全仓（#651）
- 新增 `claim-lint`：注释里的外部行为断言必须带可复核出处——起因是「酷狗/QQ 严格防盗链」这句无出处注释撑起了三个 issue 的风险讨论，五臂实测证明前提从未被证实（#647）
- 敏感扫描扩到源码（.ts/.tsx/.kt，且不跳过 __tests__），堵住「密钥 / 订阅地址写在源码里无人拦」的盲区
- staged lint 分批跑，修 Windows 命令行长度上限；`comment-gate` 真正接进 verify（此前是假门禁）（#654）
- Expo SDK 57 基线收口，全仓只保留一份 `expo`，修 `expo-check` 的红（#599 / #648）
- npm audit 定点修：critical 归零、16 → 9；移除已无消费者的 uuid override（#578 / #656）
- 主进程测试超时对齐 renderer（20s）、TTL 用例改假时钟，消掉与改动无关的 flake（#510）
